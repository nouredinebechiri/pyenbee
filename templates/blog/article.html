Qu'est-ce qu'un WAF ? Principes et mise en pratique avec ModSecurity

Découvrez le rôle d'un pare-feu applicatif web face aux cyberattaques, un panorama des solutions open source disponibles, et comment déployer le vôtre pas à pas.

NB
Enbee
IT Solution Architect
· 09/08/2026 · 12 min de lecture

Un WAF (Web Application Firewall) est un pare-feu spécialisé, placé en coupure devant une application web, dont le rôle est d'analyser le trafic HTTP/HTTPS afin de détecter et bloquer les attaques applicatives : injections SQL, XSS, inclusion de fichiers, ou encore abus de bots.

Contrairement à un pare-feu réseau classique qui filtre sur des critères IP/port, le WAF inspecte le contenu des requêtes à un niveau applicatif, ce qui lui permet de comprendre le contexte d'une attaque plutôt que de simples paquets.

i Un WAF complète une bonne hygiène de développement (validation des entrées, requêtes préparées) — il ne la remplace jamais.

01.Pourquoi déployer un WAF ?

Les applications web exposées sur Internet sont scannées en continu par des robots automatisés à la recherche de vulnérabilités connues. Un WAF permet de :

  • Bloquer les tentatives d'injection SQL et de Cross-Site Scripting (XSS)
  • Limiter les attaques par déni de service applicatif (rate limiting)
  • Virtuellement patcher une vulnérabilité en attendant un correctif
  • Journaliser finement le trafic malveillant pour l'analyse forensic

02.Panorama des solutions open source

Plusieurs projets open source permettent de déployer un WAF sans licence propriétaire :

  • ModSecurity — le plus répandu, couplé au jeu de règles OWASP Core Rule Set (CRS)
  • Coraza — une réécriture moderne en Go, compatible avec les règles ModSecurity
  • NAXSI — un module léger pour Nginx, basé sur un système de score

Comparatif rapide

ModSecurity reste la référence pour sa maturité et sa communauté, mais Coraza gagne du terrain grâce à de meilleures performances et une intégration plus simple avec les architectures cloud-native.

03.Déployer ModSecurity avec Nginx

Sur Debian/Ubuntu, l'installation passe par la compilation du module dynamique puis son chargement dans la configuration Nginx :

bash — installation 
# installer les dépendances de compilation
sudo apt install -y build-essential libpcre3-dev \
  libxml2-dev libcurl4-openssl-dev

# cloner ModSecurity et le connecteur nginx
git clone --depth 1 https://github.com/SpiderLabs/ModSecurity
git clone https://github.com/SpiderLabs/ModSecurity-nginx.git

Une fois le module compilé, on l'active dans le fichier de configuration principal de Nginx :

/etc/nginx/nginx.conf 
load_module modules/ngx_http_modsecurity_module.so;

http {
    modsecurity on;
    modsecurity_rules_file /etc/nginx/modsec/main.conf;
}
Pensez à démarrer en mode DetectionOnly avant de passer en blocage actif, le temps d'ajuster les règles à votre application et d'éviter les faux positifs.

04.Pour aller plus loin

Une fois le WAF en place, il convient de superviser ses journaux (via un SIEM ou simplement Grafana + Loki), d'automatiser la mise à jour du jeu de règles OWASP CRS, et de tester régulièrement son efficacité avec des outils comme OWASP ZAP.
